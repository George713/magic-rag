# Domain documentation

This repository uses a single domain context.

Before exploring domain behavior, read the root [GLOSSARY.md](../../GLOSSARY.md) and the [ADRs](../adr/) relevant to the area. Use the glossary's canonical terms in issues, designs, tests, and code. Surface conflicts with existing ADRs explicitly when proposing a different direction.

The [design document](../design.md) records accepted behavior and remaining integration uncertainties. Keep domain definitions in the glossary and architectural trade-offs in ADRs. Create new entries when a term or meaningful decision is resolved.
